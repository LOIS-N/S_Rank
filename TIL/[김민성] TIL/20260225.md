## 1) 전세(임대차) + 블록체인: “아이디어가 아니라 실제 운영/근거” 중심으로 조사

### 핵심 결론
- **주택 전세 계약서 자체를 “블록체인에 저장해주는 전세 전용” 단일 서비스는 흔치 않다.**
- 대신 현실적으로는 아래 2축이 강하다:
  1) **공공 전자계약/행정연계**(전세 실사용 중심)
  2) **블록체인 기반 전자문서 보관·증명 / 전자계약 인프라**(전세 계약서에도 적용 가능)

### 확인한 사례(뉴스 근거 기반)
- **KT에스테이트**: 빌딩(오피스·상가) 임대차 전자계약에 블록체인 적용 사례
- **전세스캐너(Jeonse Scanner)**: 전월세 계약 정보의 블록체인 등록/열람(사기 예방 취지) — 프로토타입 성격
- **BusinessOn SmartEContract**: 블록체인 기반 전자계약(문서 무결성/증명) 인프라 성격
- **정부(정책브리핑)**: 부동산 종합공부 관련 블록체인 시범 언급(계약서 저장 플랫폼이라기보단 공적 장부/증명 인프라 축)

### “할루네이션 2차 자가검증” 결과
- 국내 주요 주장(KT에스테이트/전세스캐너/BusinessOn/정부자료)은 기사·공식 자료로 **근거 확인됨**
- 해외(두바이 DLD)는 “2017년 블록체인 부동산 플랫폼/이니셔티브” 큰 줄기는 확인되나,
  - 내가 이전에 “임대(lease) 등록 포함”을 **로이터 단독 근거처럼 강하게 단정한 뉘앙스는 과장 가능** → 표현을 더 보수적으로 수정하는 게 안전하다고 결론

## 5) Phaser(페이저) 엔진 개요 정리

### Phaser 핵심
- 웹(HTML5) 기반 **2D 게임 프레임워크**
- Scene 구조(`preload / create / update`), 입력/오디오/애니메이션/타일맵/카메라/물리(Arcade/Matter) 지원
- Phaser 3는 안정, Phaser 4는 RC/beta 흐름 존재

## 6) 방치형 “채굴” 게임 공통 특징 정리

### 공통 구조(요약)
- **생산(채굴) → 수집(정산) → 업그레이드(투자) → 자동화 → 티어 이동/반복**
- 비용은 지수적으로, 생산은 곱연산으로 성장 → **인플레 제어가 핵심**
- 오프라인 보상은 보통 **상한(캡) + 재접속 보너스**로 설계
- 장기 재미는 **프레스티지(환생/리셋) + 영구 업그레이드 트리**가 담당
- RNG는 희귀 드랍/이벤트로 양념, 과하면 피로 → 천장/누적 보정이 흔함
- Web3/NFT가 붙으면 **거래 가능한 생산 자산**이 생기므로 밸런스 붕괴 방지(소각/내구도/시즌 구조)가 중요
