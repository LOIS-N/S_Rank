건설 노동자 보완 아이디어

월급/주급/일급/시급으로 구분해서 일급은 건설 노동자 위주로 하는 방식 고려중

아래는 주로 일급을 현금으로 받는 케이스가 많다 보니 플랫폼 편의성 개선 고민

좋은 고민이에요. **건설 현장 임금 체불 문제는 “기술”보다 “현장 사용성 + 제도 연결”이 핵심**이라서, 단순히 지갑 만들어서 토큰 보내는 구조는 거의 실패합니다. 실제로 많은 Web3 프로젝트가 여기서 망했어요.

핵심은 이렇게 정리됩니다:

> ✅ 노동자는 “지갑을 쓴다”는 느낌이 없어야 함
> 
> 
> ✅ 현장에서는 “기존 계좌/문자/카톡 수준”으로 간단해야 함
> 
> ✅ 블록체인은 뒤에서 “증빙·자동정산·추적” 역할만 해야 함
> 

아래에 **현실적으로 작동 가능한 아키텍처**를 단계별로 설명할게요.

---

# 👍 1️⃣ “지갑 없는 지갑 (Invisible Wallet)” 모델이 답

요즘 실무에서는 **Account Abstraction + Custodial Hybrid**를 씁니다.

## 어떻게 동작하냐면:

- 노동자 → 휴대폰 번호로 가입 (OTP 인증)
- 백엔드 → 자동으로 지갑 생성
- 개인키 → 서버/HSM 또는 MPC로 관리
- 노동자 → 그냥 “급여 조회 앱”처럼 사용

즉:

👉 노동자는 지갑 존재를 모름

👉 그냥 급여 앱처럼 씀

이게 현재 가장 성공률 높은 방식입니다.

---

## UX 흐름 예시

1️⃣ 현장 출근 → QR 찍거나 관리자 승인

2️⃣ 근무 기록 → 블록체인에 해시 기록

3️⃣ 일급 확정 → 스마트컨트랙트 lock

4️⃣ 지급 버튼 → 계좌로 입금 or 선불카드 충전

노동자는:

> “오늘 일한 돈 들어왔네”
> 

이 정도 경험만 합니다.

# 👍 2️⃣ 온체인 정산 + 오프체인 지급 (핵심 전략)

여기서 중요한 포인트:

> 돈은 굳이 코인으로 줄 필요 없음
> 

실제로는 이렇게 합니다:

| 역할 | 방식 |
| --- | --- |
| 계약 기록 | 블록체인 |
| 임금 계산 | 스마트컨트랙트 |
| 실제 지급 | 은행 API |
| 증빙 | 온체인 |

즉:

👉 블록체인은 “분쟁 방지 장부”

👉 돈은 “현실 화폐”

이게 규제도 안전합니다.

- 근무 기록 방식 → gps 기반 지동 체크? 수동 체크(버튼 클릭 방식) …

좋아. “근무기록(출역) 오라클”을 **현장에서 실제로 굴러가게** 하려면, 각 옵션을 “어떤 화면/흐름/데이터/부정 방지/예외처리”까지 내려가야 함. 아래에 A/B/C를 **운영 시나리오 기준**으로 구체화해줄게. (블록체인은 “최종 증빙/정산 트리거”로만 쓰는 전제)

---

## 공통 전제: 근무기록 데이터 모델(최소)

현장에선 복잡하면 안 되니까, 근무 이벤트는 이렇게 단순하게.

- `worker_id` (휴대폰 기반 내부ID)
- `site_id` (현장)
- `event_type` = `IN` / `OUT` / `BREAK_START` / `BREAK_END` (선택)
- `timestamp` (서버 기준 + 단말 기준 같이 저장)
- `proof` (옵션별 증빙: 서명, QR토큰, 게이트로그 등)
- `approver_id` (A옵션에서)
- `confidence_score` (부정탐지용, 0~100)
- `hash_onchain` (원본은 오프체인, 해시/머클루트만 온체인)

**원본 데이터(개인정보/위치/게이트로그)는 오프체인**에 저장하고

- *온체인엔 “변조 방지용 해시 + 요약”**만 올리는 게 현실적으로 맞음.

# 옵션 A) 관리자 + 노동자 이중 서명 (현장 최다 적용)

### 핵심 컨셉

“노동자가 체크인 요청 → 관리자가 승인(서명) → 확정”

- 장점: 단순, 교육 쉬움, 스마트폰만 있으면 됨
- 단점: 관리자가 바쁘면 병목 / 관리자-노동자 담합 가능성

### 추천 UX 흐름(최적)

### 1) 노동자 체크인(10초)

- 노동자 앱: **[출근하기]** 버튼 1개
- 누르면 “출근요청 생성”
    - 서버가 **1회용 체크인 토큰** 발급(유효 2~3분)
    - 노동자 화면에 “요청 완료” 표시

### 2) 관리자 승인(5~20초)

관리자 앱/태블릿: “대기중 출근요청 리스트”

- 이름/연락처 뒤4/직종/팀/요청시간만 보여줌(개인정보 최소)
- 관리자: **[승인]** 탭 → 끝
- 승인 시 서버가 `approver_signature` 생성(관리자 권한 서명)

### 3) 확정(자동)

- 노동자: “출근 확정” 푸시/카톡 알림
- 이후 정산 컨트랙트에 “오늘 IN 이벤트 해시” 등록

### 부정/악용 방지(중요)

A옵션의 약점은 “관리자 마음대로 찍어주기”라서 **가벼운 방지장치**를 추천함.

- **현장 근처에서만 체크인 요청 가능(지오펜스)**: 반경 300~800m
- **관리자 승인 시 사진 1장 옵션** (강제하면 UX 망, “랜덤 요구”로)
- **1일 1회 랜덤 감사**: 특정 작업자/시간대만 “추가 인증”
- **승인 권한 분리**: “소장”만이 아니라 “반장/안전관리자” 등 다중 승인자 풀
- **이상치 탐지**:
    - 너무 많은 인원을 1분 안에 승인
    - 매일 같은 시간에 동일 패턴
    - GPS/게이트 로그와 반복 불일치
        
        → `confidence_score` 낮추고 자동 플래그
        

### 예외처리(현장 필수)

- **폰 없음/배터리 없음**: 관리자가 “대리 체크인” 가능 (단, “대리” 태그 + 사유 + 추후 노동자 확인)
- **관리자 부재**: “임시승인자” 지정(권한 위임) + 시간 제한
- **통신 불량**: 오프라인 큐(단말에 저장) → 통신 복구 시 업로드, 단 `server_time` 기반 재정렬

# 옵션 B) GPS + QR (관리자 병목 줄이기용)

### 핵심 컨셉

“현장에 있는 QR을 찍으면 자동 체크인”

- 장점: 관리자 부담 감소, 대기열 처리 빠름
- 단점: QR 공유/캡처로 대리출근 위험, GPS는 위조 가능(루팅/스푸핑)

그래서 **QR만** 쓰면 깨지고, **QR + 서버챌린지 + 위치/시간**을 묶어야 함.

### 추천 설계: “회전(rolling) QR + 1회용 토큰”

### 1) 현장 게시물(고정이 아니라 ‘회전’)

- 현장에 태블릿/TV/키오스크/관리자 폰으로 **QR을 계속 갱신(예: 30초마다)**
- QR 내용은 단순 URL이 아니라:
    - `site_id`
    - `nonce`
    - `valid_until`
    - `signature_by_server`

### 2) 노동자 체크인

- 노동자 앱이 QR을 스캔하면
    - 서버에 nonce 제출
    - 서버가 검증 후 “IN 이벤트” 생성
    - 동시에 **추가 신호** 수집:
        - GPS(필수)
        - Wi-Fi BSSID(선택, 현장 공유기 있으면 강력)
        - 단말 무결성(루팅/개발자모드 감지)

### 부정 방지 포인트(이게 핵심)

- **정적 QR 금지**: 인쇄해두면 카톡으로 돌림 → 끝장
- **짧은 유효시간(30~60초)**: 캡처 공유해도 거의 무용
- **지오펜스**: 반경 설정
- **Wi-Fi/Bluetooth 비콘**(가능하면 강추)
    - 현장에 2~3개 비콘 설치(저렴)
    - “비콘 신호 감지 + QR” 조합이면 GPS 스푸핑 상당 부분 잡힘
- **고위험 단말 차단**:
    - 루팅/탈옥 감지
    - 모의위치 ON 감지
    - 의심이면 “관리자 확인 모드”로 전환(옵션 A로 fallback)

### 예외처리

- **비 오는 날/장갑/현장 동선**: QR 위치를 “게이트 1곳”만 두면 줄 생김
    
    → **동선별 QR 포인트 2~3개**가 좋음(출입구/자재반입구/사무실 앞)
    
- **야간 작업/조명**: 카메라 스캔 실패 대비 “NFC 태그”도 고려(대체수단)

# 옵션 C) 출입카드/게이트 시스템 연동 (운영 안정성 최고)

### 핵심 컨셉

“이미 현장에 있는 출입관리 로그를 근무기록으로 사용”

- 장점: 노동자 UX 거의 0, 부정 난이도 높음, 관리비용 낮아짐
- 단점: 현장마다 시스템이 달라서 **연동 비용/표준화**가 관건

### 실제 구현 방식 2가지

### C-1) API 직접 연동(이상적)

- 출입통제 솔루션이 API/DB 접근 제공하면
    - `card_id`, `gate_id`, `timestamp`, `direction(IN/OUT)`을 주기적으로 가져옴
    - worker 매핑은 최초 1회만:
        - 카드번호 ↔ worker_id 연결(관리자 또는 본인 인증)
- 가져온 로그를 “근무 이벤트”로 변환

### C-2) 파일 드롭/배치 연동(현실적, 초반 MVP에 강추)

API가 없는 경우가 더 많음. 그래서:

- 출입시스템에서 **CSV/엑셀**로 로그를 뽑게 하고(대부분 가능)
- 이를 업로드하면 자동 파싱/정합성 체크 후 반영

초기 시장 진입은 C-2가 훨씬 빠름.

### 부정/오류 처리

- **꼬리물기(뒤따라 들어가기)**: 출입 로그만으론 100% 못 막음
    
    → 랜덤 QR 체크(옵션 B)를 “감사 모드”로 섞으면 좋음
    
- **퇴근 OUT 누락**: 야근/외출/재입장 등 때문에 흔함
    
    → 규칙 기반 처리:
    
    - OUT이 없으면 기본 근무시간 상한(예: 12h) 적용 후 플래그
    - 다음날 첫 IN 전까지 OUT 추정(정책 선택)
- **게이트 우회 출입**: 작업 구역별 게이트 커버리지 확인 필요
    
    → 최소 “주출입구”만 연동해도 체불 분쟁의 증빙가치는 큼
    

### UX (노동자)

- 아무것도 안 함
- 앱에서 “오늘 출근/퇴근 찍힘”만 확인

이게 진짜 강력.

# 추천 조합(현실 베스트)

현장/사업 단계별로 이렇게 가는 게 제일 실효성 높음.

## 1단계(MVP, 도입 쉬움): A + (약한 지오펜스)

- 관리자 승인 기반으로 시작
- 현장 적응/교육/채용 없이 돌아감

## 2단계(확장, 병목 해결): A + B (QR 자동 + 예외는 관리자)

- 평소엔 QR로 자동 처리
- 의심/예외만 관리자 승인으로 fallback

## 3단계(성숙, 운영비 절감): C 중심 + B 감사모드

- 게이트 로그가 메인
- 랜덤 QR/비콘은 부정 방지 감사로 사용

# 온체인에는 무엇을 올리나 (구체)

현실적으로 온체인에는 이런 것만 올리는 게 좋음:

- 하루 단위 `attendance_digest` (머클루트)
- `site_id`, `date`, `total_workers`, `approved_by_oracle_signature`
- 분쟁 시에만 “특정 worker의 원본 이벤트”를 오프체인에서 제출 → 해시 검증

이러면:

- 개인정보 덜 위험
- 비용 절감
- 증거 능력 유지

---

원하면 내가 다음도 바로 만들어줄게:

1. **각 옵션별 화면 와이어프레임(텍스트로)**
2. **부정 방지 룰셋(탐지 지표/점수화)**
3. **근무기록 → 일급정산으로 이어지는 컨트랙트 이벤트 설계**

일단 너는 “현장에 이미 출입게이트가 많다/없다”, “관리자 1명이 몇 명을 관리하냐” 이 두 개 중 하나만 대충 알려줘. 그거 기준으로 최적 조합을 더 구체적으로 박아줄게.
