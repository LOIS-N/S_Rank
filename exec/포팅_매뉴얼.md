## 4. 서버 초기 설정

### 4.1 Docker 설치

```bash
# 패키지 업데이트
sudo apt-get update
sudo apt-get upgrade -y

# Docker 설치를 위한 필수 패키지
sudo apt-get install -y \
    ca-certificates \
    curl \
    gnupg \
    lsb-release

# Docker 공식 GPG 키 추가
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
    sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# Docker 저장소 추가
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Docker 설치
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Docker 서비스 시작 및 자동 시작 설정
sudo systemctl start docker
sudo systemctl enable docker

# 현재 사용자를 docker 그룹에 추가 (sudo 없이 docker 사용)
sudo usermod -aG docker $USER
newgrp docker
```

### 4.2 방화벽 설정 (UFW)

> **주의:** UFW는 Docker와 충돌할 수 있음. Docker는 iptables를 직접 조작하므로 UFW로 막아도 Docker 포트는 열릴 수 있음. 보안 그룹(AWS)에서 포트를 제어하는 것을 권장.

```bash
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 8001/tcp
sudo ufw allow 8080/tcp
sudo ufw allow 8002/tcp
sudo ufw allow 8082/tcp
sudo ufw allow 8090/tcp
sudo ufw allow 8030/tcp
sudo ufw allow 8433/tcp
sudo ufw allow 8647/tcp
sudo ufw allow 8648/tcp
sudo ufw allow 8672/tcp
sudo ufw allow 8673/tcp
sudo ufw allow 8674/tcp
sudo ufw enable
```

### 4.3 Docker 네트워크 생성

```bash
docker network create gateway-net
docker network create infra-net
```

## 6. Gateway 설정 (Nginx + SSL)

### 6.1 docker-compose.yml

**파일 위치:** `~/cicd/gateway/docker-compose.yml`

```yaml
version: '3.8'

services:
  nginx:
    image: nginx:1.25-alpine
    container_name: gateway-nginx
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
      - "8080:8080"
      - "8001:8001"
      - "8082:8082"
      - "8002:8002"
      - "8090:8090"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - certbot-conf:/etc/letsencrypt:ro
      - certbot-www:/var/www/certbot:ro
      - /home/ubuntu/assets:/home/ubuntu/assets:ro
    deploy:
      resources:
        limits:
          memory: 256m
    networks:
      - gateway-net
    depends_on:
      - certbot

  certbot:
    image: certbot/certbot:latest
    container_name: gateway-certbot
    volumes:
      - certbot-conf:/etc/letsencrypt
      - certbot-www:/var/www/certbot
    entrypoint: "/bin/sh -c 'trap exit TERM; while :; do certbot renew --webroot -w /var/www/certbot; sleep 12h & wait $${!}; done;'"

volumes:
  certbot-conf:
    name: certbot-conf
  certbot-www:
    name: certbot-www

networks:
  gateway-net:
    name: gateway-net
    external: true
```

## 7. 공용 서비스 설정 (PostgreSQL + Redis)

### 7.1 docker-compose.yml

**파일 위치:** `~/cicd/common/docker-compose.yml`

```yaml
version: '3.8'

services:
  postgres-dev:
    image: postgres:15-alpine
    container_name: postgres-dev
    restart: unless-stopped
    ports:
      - "8433:5432"
    environment:
      POSTGRES_DB: ${POSTGRES_DEV_DB}
      POSTGRES_USER: ${POSTGRES_DEV_USER}
      POSTGRES_PASSWORD: ${POSTGRES_DEV_PASSWORD}
      PGDATA: /var/lib/postgresql/data/pgdata
    volumes:
      - postgres-dev-data:/var/lib/postgresql/data
    deploy:
      resources:
        limits:
          memory: 1g
    networks:
      - infra-net
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_DEV_USER} -d ${POSTGRES_DEV_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5

  postgres-prod:
    image: postgres:15-alpine
    container_name: postgres-prod
    restart: unless-stopped
    ports:
      - "8647:5432"
```

## 19. 배포 특이사항

### 19.1 FE 환경변수는 반드시 재빌드 필요

`NEXT_PUBLIC_` 접두사 변수는 Next.js 빌드 타임에 번들에 하드코딩됨.
`.env` 파일을 수정한 후 `docker compose up -d`만 실행해서는 변경이 반영되지 않음.
**반드시 Jenkins 파이프라인을 통해 재빌드해야 함.**

### 19.2 deploy-prod는 Pipeline script 방식으로 관리

`deploy-prod` 파이프라인은 SCM에서 Jenkinsfile을 읽지 않고 Jenkins UI에 직접 입력된 스크립트를 사용함.
이는 master 브랜치 merge 시 Jenkinsfile이 덮어써지는 것을 방지하기 위함.

### 19.3 서비스 기동 순서 준수

`common`(DB/Redis) → `gateway`(Nginx) → `jenkins` → `monitoring` → App 순서로 기동해야 함.
App 컨테이너(dev-be, prod-be 등)는 DB가 먼저 실행되어야 정상 시작됨.

### 19.4 Docker 네트워크 사전 생성 필수

```bash
docker network create gateway-net
docker network create infra-net
```

이 네트워크가 없으면 모든 컨테이너가 실행 실패함.

### 19.5 Privy 허용 Origin 등록 필요

Privy 대시보드(privy.io)에서 프로젝트 허용 Origin에 아래 URL을 모두 등록해야 함:
- `https://j14e204.p.ssafy.io` (prod)
- `https://j14e204.p.ssafy.io:8001` (dev)
- `https://j14e204.p.ssafy.io:8002` (hotfix)

### 19.6 Sentry DSN 설정

Sentry는 FE 코드 내부(`sentry.client.config.ts` 등)에 DSN이 하드코딩되어 있음.
`NEXT_PUBLIC_SENTRY_ENVIRONMENT` 환경변수로 dev/prod 환경만 분기함.

## 22. 유지보수 명령어 모음

### 컨테이너 상태 확인

```bash
# 전체 컨테이너 상태
docker ps -a

# 리소스 사용량
docker stats --no-stream
```

### 로그 확인

```bash
# 실시간 로그
docker logs -f [컨테이너명]

# 최근 100줄
docker logs [컨테이너명] --tail=100

# 에러만 필터
docker logs [컨테이너명] --tail=200 2>&1 | grep -i "error\|exception"
```

### 컨테이너 재시작

```bash
docker restart [컨테이너명]
```

### 특정 환경만 내리기

```bash
# Dev 환경 중단
cd ~/cicd/develop && docker compose down

# Prod 환경 중단
cd ~/cicd/release && docker compose down

# Hotfix 환경 중단
cd ~/cicd/hotfix && docker compose down
```

### 디스크 정리

```bash
# 미사용 이미지 정리
docker image prune -a -f

# 전체 정리
docker system prune -f
```

### 서버 재부팅 후 복구 순서

```bash
docker network create gateway-net
docker network create infra-net

cd ~/cicd/common && docker compose up -d
cd ~/cicd/gateway && docker compose up -d
cd ~/cicd/jenkins && docker compose up -d
cd ~/cicd/monitoring && docker compose up -d
# Dev/Prod/Hotfix는 Jenkins에서 재빌드
```

## 23. 문제 해결 (Troubleshooting)

### 502 Bad Gateway

```bash
# 뒤에 있는 컨테이너 확인
docker ps | grep dev-be
docker ps | grep dev-fe

# Nginx 설정 문법 확인
docker exec gateway-nginx nginx -t

# Nginx 재적용
docker exec gateway-nginx nginx -s reload
```

### 컨테이너가 계속 재시작됨

```bash
# 종료된 컨테이너 로그 확인
docker logs [컨테이너명] --tail=100
```

### Jenkins 빌드 실패

```bash
# Jenkins UI → 해당 빌드 → Console Output 확인
# 호스트에서 직접 docker compose build 실행 금지
# 반드시 Jenkins UI에서 빌드 트리거
```

### Grafana 비밀번호 분실

```bash
docker exec grafana grafana cli admin reset-admin-password 'Gr@f4na!24'
```

> `!` 문자가 포함되어 있으므로 반드시 싱글 쿼트(`'`) 사용.

### SSL 인증서 만료

```bash
docker exec gateway-certbot certbot renew
docker exec gateway-nginx nginx -s reload
```

### DB 연결 실패

```bash
# DB 컨테이너 상태 확인
docker ps | grep postgres

# DB 직접 접속 테스트
docker exec postgres-dev psql -U ssafy_dev_user -d ssafy_dev -c "SELECT 1;"
docker exec postgres-prod psql -U ssafy_prod_user -d ssafy_prod -c "SELECT 1;"
```
